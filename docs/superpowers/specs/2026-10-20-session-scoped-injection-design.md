# 单会话热注入与热撤销注入 · 设计

日期：2026-10-20
状态：待批准

---

## 一、意图

当前插件的提示词注入是**全局**的：`cordis.patch.yml` 的 `personaSuffix`、`prompt-inject.md`
对所有会话一视同仁，改了要重启宿主才刷新。用户想要的是**按会话独立控制**：

- 多个会话并行时，各自保持自己的注入状态；
- 同一个会话可以中途开启或关闭，不用重开；
- 临时试错时不必改动全局配置；
- 不同会话可以用不同预设。

**切换后在下一轮生效**，不中断当前正在生成的回复。

## 二、目标与非目标

### 目标

| # | 目标 |
| --- | --- |
| G1 | 每个会话独立记录「是否注入」与「注入用哪份内容」 |
| G2 | 状态持久化到磁盘，宿主重启后仍在 |
| G3 | 切换后下一轮生效，不需要重启宿主 |
| G4 | 支持热撤销：关掉后该会话下一轮就回到未注入状态 |
| G5 | 提供 UI 与 CLI 两种操作入口 |
| G6 | 默认关闭，但升级时给出醒目提示，避免「以为插件坏了」 |

### 非目标

| # | 不做 |
| --- | --- |
| N1 | 不中断正在生成的回复（用户明确选择「下一轮生效」） |
| N2 | 不改宿主源码里的会话存储格式 |
| N3 | 不改变全局配置的语义——全局配置仍是「默认值」，只是不再无条件生效 |
| N4 | 不做跨设备同步 |

### 反目标（这样算失败）

| # | 失败条件 |
| --- | --- |
| A1 | 升级后用户不知道注入被关了，以为插件失效 |
| A2 | 会话状态串味：A 会话的开关影响 B 会话 |
| A3 | 状态文件损坏导致插件起不来 |
| A4 | 子代理会话行为异常（它们继承父会话，需明确规则） |

## 三、关键约束

1. **注入函数能拿到会话**：`context.agent.session`，已有 `sessionOfContext()` 在用（`identity.js:384`）。
   会话稳定标识用 `session.header.id`。
2. **默认全关**：新会话默认不注入。这是用户明确选择，但必须配 A1 的缓解措施。
3. **子代理**：子代理会话继承父会话的状态，不单独存储（否则每派一个子代理都要配一次）。
4. **状态文件位置**：`$DSH_HOME/dsh-purge/session-inject.json`，与现有 `override-state.json`、
   `host-backups/` 同目录。

## 四、状态模型

```json
{
  "version": 1,
  "sessions": {
    "<sessionId>": {
      "enabled": true,
      "source": "override" | "preset" | "default",
      "text": "注入正文（可选；source=default 时为空）",
      "presetId": "可选，预设标识",
      "updatedAt": "2026-10-20T09:00:00.000Z"
    }
  }
}
```

**判定顺序**（每轮 assemble 时）：

```
1. 子代理？ -> 用父会话的状态；父也没有则用 default
2. 该 sessionId 有记录？ -> 用记录
3. 没有记录 -> default（enabled=false）
```

`source` 只用于 UI 显示与诊断，不参与判定。

## 五、为什么默认全关需要醒目提示

这是本设计里**唯一会让现有用户感到「功能消失」的改动**。缓解措施：

| 措施 | 说明 |
| --- | --- |
| 首次升级横幅 | 检测到状态文件不存在（= 首次运行新版本）时，在侧栏面板顶部显示一次性横幅：「注入已改为按会话控制，当前会话未启用。点此启用」 |
| 页签红点 | 当前会话未注入时，右侧栏页签标题旁显示一个提示点 |
| CLI 提示 | `--status` 里单独一行报告当前会话的注入状态与全局默认 |
| 文档 | README 的「工作原理」段落改写，说明新的默认行为 |

横幅用 `localStorage` 记「已展示过」，不写进状态文件（避免和用户数据混在一起）。

## 八、留给实现的决定

以下我按工程判断定，不单独问：

- 状态文件写入用现有的 `atomicWriteSync`，并发写用进程内串行队列；
- 状态文件损坏（JSON 解析失败）时**不删文件**，备份成 `.corrupt` 后按默认值启动，
  避免静默丢用户配置；
- 会话 id 取不到时按「默认关闭」处理，并记一条日志——宁可不注入，也不要错误注入到别的会话。
